# Проверка расчётов и границы применимости

## Автоматические проверки

Запуск: `python -m pip install -r requirements-test.txt`, затем
`python -m pytest -q -ra tests`. GitHub Actions запускает тот же набор на Windows
и Linux с Python 3.11/3.12. Отчёт JUnit и полный список версий сохраняются в
артефактах каждого запуска. Ориентируйтесь на статус последнего коммита.

Проверяются:

- чтение/запись EDI, статический сдвиг, постоянный и частотно-зависимый ZROT/TROT;
- нулевой и прямоугольный поворот при отсутствующих диагоналях, отказ от
  выдуманных компонент при косом повороте;
- аналитическое однородное полупространство для 1D;
- независимая 1D-рекурсия против 2D-решателя для слоистой среды;
- однородная 2D-модель на двух сетках;
- производные, сопряжённость и обновление кэша Якобиана;
- геометрия рельефа и возврат к плоскому пределу;
- полный путь TE+TM-инверсии известного полупространства;
- восстановление слоя 1D-инверсией, совместная АМТЗ/ЗСБ-инверсия и сдвиг;
- независимое сравнение прямой задачи ЗСБ с empymod;
- создание интерфейса, импорт Цикл и другие существующие регрессии.

Проверки простых моделей обнаруживают ошибки реализации. Они не доказывают,
что любая сложная структура на полевом разрезе разрешена данными.

## Ориентация и ошибки EDI

При импорте вращение устраняется отдельно на каждой частоте. Внутри Station
импортированные данные хранятся в географических осях. При экспорте углы текущей
системы координат записываются в ZROT/TROT, статический сдвиг применяется один раз.
Погрешности при повороте распространяются в предположении независимости исходных
компонент. Полная ковариация EDI не хранится; последовательные повороты не обязаны
восстанавливать исходные ошибки. Файлы только со спектрами не поддерживаются.

## Рельеф

Это ступенчатое приближение на TensorMesh, а не конформная сетка. Поверхность
интерполируется между станциями и продолжается постоянной в боковых отступах.
Приёмник привязывается к верхней грани земли в своём столбце. Проверяйте сообщение
о максимальной ошибке привязки и сгущайте сетку на крутом/сложном рельефе.
Отсутствующая в EDI высота пока трактуется как 0 м: такие отметки необходимо
исправить в исходных файлах или отключить рельеф для диагностического сравнения.

## Чувствительность не равна достоверности

Затенение использует сумму модулей взвешенных производных, делённую на площадь,
сглаженную и нормированную на 99-й процентиль. Порог 1% условен и зависит от сетки,
ошибок и нормировки. Это индикатор чувствительности, не формальный DOI и не
доверительный интервал. Названия методов `doi_mask`/`doi_depth` оставлены ради
совместимости со старыми скриптами.

Перед использованием полевой структуры в геологическом выводе:

1. Сравните минимум две сетки, несколько стартовых сопротивлений и весов
   регуляризации, не только итоговый RMS, но и остатки по модам/частотам/станциям.
2. Проверьте допустимость 2D и выбранного простирания; 3D-эффекты не исправляются
   уменьшением регуляризации или статическим сдвигом.
3. Уберите спорную структуру и оцените ухудшение подбора, проверьте синтетику
   на фактической расстановке с реалистичным шумом и отложенные станции.
4. Сопоставьте с независимой геологией/скважинами/другими измерениями.

Такие проверки для полевых профилей не выполнены автоматически: исходные полевые
данные и внешние ограничения в репозитории отсутствуют. Описания старых результатов
в HANDOFF.md не являются повторной валидацией новой версии программы.
